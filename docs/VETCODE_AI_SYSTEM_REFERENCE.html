Overview

VETCODE uses OpenAI-backed features as a workflow intelligence layer over recruiting, certification, onboarding, CRM, meetings, time, and accounting. The AI does not replace the application database. It reads scoped context, drafts structured outputs, recommends next actions, and in controlled cases prepares app actions that still require user confirmation.

1. Gather Context Page, domain, candidate, job, CRM, schedule, and recent chat state are collected.
2. Prompt Agent The selected agent receives a page-specific role prompt plus safety policy.
3. Structure Output Resume, job, action, schedule, and CRM prompts prefer JSON or tightly constrained text.
4. Save Through App Confirmed outputs are saved through deterministic app endpoints, not arbitrary model writes.

Numa and Egeria

Page-Aware Assistant

Numa

Numa is the main page-aware assistant framework. Numa changes behavior by active page: Talent, Profiles, Job Descriptions, CRM, Meet, Interviews, Time, Accounting, Invoices, Certification, Badge Catalog, Reports, and Admin.

Primary job: explain what is happening, guide the user, summarize page context, warn about missing data, and prepare controlled app actions when permitted.

Key files: backend/openAI/pageAgents.py and backend/ui/pages/JS/pageAgents.js.

Process Agent

Egeria and FastBoard

Egeria is the guided process-flow agent. Her first implemented workflow is FastBoard Candidate Launch, a safe rapid consultant launch path that asks for the job need, drafts a JD, waits for approval, creates the JD, ranks candidates, waits for candidate approval, seeds shortlist/status, and prepares scheduling.

Primary job: move the user through a whole process, keep the domain and candidate/job context intact, and offer rollback/resume if the flow is interrupted.

Key files: backend/ui/pages/components/processFlow.html, backend/ui/pages/components/sideNav.html, and backend/openAI/pageAgents.py.

AI Data Storage

PostgreSQL Source of Truth

Candidate/profile, job, skills, survey, and platform activity records are stored in Azure PostgreSQL through backend/azureUtils/storage/client.py.

Important tables include person, professional, professionalprofile, professionalexperience, professionalskill, resumeskill, skill, jobdescription, jobskills, jobpersonalities, aichatlogs, professionalsurvey, and professionalsurveyquestion.

JSON Operational Stores

Newer workflow areas use JSON stores under backend/data and are domain-filtered in app logic.

Key files: workflow_events.json, crm_records.json, meeting_records.json, onboarding_records.json, time_entries.json, accounting_records.json, profile_badges.json, interview_archive.json, and profile_completion_chats.json.

Browser State

AI workflow context uses browser state for active candidate, active job, domain, shortlist, recent agent chat, and FastBoard recovery state.

Examples: sessionStorage.candidateId, selectedJdId, jobTitle, shortlistDetails:{domain}, devreadyAgentChat:{agent}:{domain}, and egeriaQuickHitState:{domain}.

Blob / File Storage

Resume files are stored through Azure Blob when storage credentials are configured. The AI profile pipeline stores extracted structured data separately from the original uploaded file.

Key file: backend/azureUtils/storage/resumes.py.

Prompting Model

VETCODE uses task-specific prompts instead of one giant general prompt. The app wraps the model call with deterministic context and then validates or filters the output before using it.

Prompt Type Purpose Guardrail
Page-agent role prompt Tells Numa or Egeria which page/process they own and how to speak. Loaded from AGENTS in pageAgents.py; can be overridden through agent admin context.
Safety policy prompt Forces no data deletion, no secret exposure, no claims of saved changes without confirmation. Redacts finance/deal/rate data unless admin/super-user unlock is present.
Action planner JSON prompt Turns clear create/update/schedule intent into structured app actions. Allows only known action types and filters by access/change policy.
Resume extraction JSON prompt Converts resume text into a structured candidate profile with portfolio rows. Requires strict JSON, clamps years, deduplicates skills, and preserves separate jobs.
Candidate chat prompt Asks the next profile/personality survey question. Answer parsing is deterministic and saved as 1-5 survey scores.
CRM news scan prompt Summarizes public news into account signals and recommended action. Uses snippets, expects JSON, and falls back when search/model is unavailable.

Safety and Controls

Human Approval

The model can draft and prepare. Persisted workflow steps require explicit app action, approval, or an authorized change mode. FastBoard uses checkpoints before creating JDs, searching, selecting a candidate, and moving to schedule/status.

Domain Isolation

Every AI call and storage write should preserve domain: Technology (dev), Engineering (engineer), or Law (law). Context, URLs, SQL filters, JSON filters, and session keys must stay aligned.

Rollback / Resume

FastBoard stores process state in egeriaQuickHitState:{domain}. Rollback clears selection context and attempts to delete a JD created during the FastBoard run.

Secret Boundary

This page names environment variables and code locations only. It must never contain secret values such as OPENAI_API_KEY, OAuth client secrets, database passwords, Azure storage connection strings, or production credentials.

Important: As Egeria gains more authority, durable server-side workflow runs should be added before allowing multi-page automated execution. The next layer should record every agent step, approval, mutation, rollback target, and result in a database-backed workflow ledger.

Specific IP / Product Logic

Note: This section describes product and implementation IP. It is not a legal patent opinion, trademark claim, or legal filing.

Domain-Scoped Talent OS

The platform separates Technology/DevReady, Engineering/BuildReady, and Law/LegalReady while reusing the same workflow engine. This allows one product to support different labor markets without cross-contaminating profiles, jobs, certifications, or CRM data.

FastBoard Candidate Launch

A guided emergency-consultant workflow that combines AI drafting, JD creation, candidate ranking, shortlist, scheduling, and status in one recoverable process with checkpoints.

Egeria Process Agent

Egeria is designed as a higher-authority process agent, distinct from general page chat. Her value is not a separate model; it is the structured permission, context, workflow memory, and rollback contract around the same model.

Evidence-Based Profile Graph

Resume data, portfolio rows, skills, culture/personality survey results, badges, certification, interview notes, onboarding, and time records all attach back to the candidate/profile.

Operational Links as Mini Apps

Sales CRM, onboarding, candidate chat, time entry, and certification are sendable focused workspaces. External users update only their slice, while the main VETCODE system receives the data back into shared records.

Closed-Loop Business Flow

Candidate selection, CRM/customer, onboarding, time, approved hours, rates, invoices, and reporting are linked. AI can eventually monitor missing links and guide users to the next business action.

Expansion Plan

The next AI build-out should make agents process-aware across pages while keeping the current approval, domain, and rollback discipline.

  • Add durable workflow_runs and workflow_events tables for Egeria.
  • Give every AI action an idempotency key, rollback target, user approval id, and result status.
  • Move FastBoard state from browser-only session storage into server-side workflow state.
  • Add per-domain AI policies for Technology, Engineering, and Law vocabulary and evidence rules.
  • Expand Egeria from FastBoard into onboarding, missing-time recovery, invoice readiness, CRM follow-up, and certification handoff.
  • Create AI audit reports showing prompts used, data touched, approvals, failures, and rollback history.
  • Keep all prompts versioned so model behavior can be compared between releases.
