Prompting is split by task: resume extraction uses strict JSON, page agents use role prompt plus safety policy plus page context, and action planning uses a separate strict JSON action schema.

Numa and Egeria

Implemented

Numa

Numa is the main page-aware assistant framework. In the code, every built-in page agent is currently named Numa or Sales Numa. Numa changes focus based on the active page: Talent, Find Candidates In, Find Candidates Out, Profiles, Job Descriptions, CRM, Meet, Interviews, Client Communication, Time, Accounting, Invoices, Test Challenge, AI Certification, Badge Catalog, and Admin.

Frontend: backend/ui/pages/JS/pageAgents.js mounts the floating Ask Numa button, gathers page context, stores recent chat memory, and sends requests to the backend.

Backend: backend/openAI/pageAgents.py stores page-specific prompts, safety policy, redaction logic, and controlled action planner.

Policy: Numa guides first. It cannot claim data changed until an app action confirms it. Sensitive financial/deal/rate data is redacted unless admin/super-user access is unlocked.

Implemented for FastBoard

Egeria

Egeria is the guided process helper. The FastBoard Candidate Launch in backend/ui/pages/components/processFlow.html presents Egeria as the assistant that asks, drafts, confirms, creates, ranks, selects, and prepares scheduling.

Current split: Egeria has her own frontend registry entry, backend agent key, and system prompt. The FastBoard workflow calls agent_key=egeria for JD drafting/action planning, then uses deterministic app steps to save the JD, rank candidates, seed shortlist/status, and offer rollback.

Next implementation target: expand Egeria beyond FastBoard into a full cross-page process governor with a gold/blue/silver visual identity, durable server-side workflow runs, and database-level transaction logging.

Developer Notes

  • Domain isolation depends on preserving domain through URLs, session storage, API calls, SQL filters, and JSON store filters.
  • Profile/job data is mostly PostgreSQL. CRM, accounting, time, onboarding, meetings, workflow, and badges are mostly JSON operational stores.
  • Main AI risk areas are resume extraction completeness, action planner overreach, external sourcing uncertainty, and sensitive financial/deal data exposure.
  • When adding AI features, keep deterministic fallback paths and clear next-step messaging when the model or API key is unavailable.
  • Egeria must stay registered in both frontend and backend agent registries so UI label, prompt, icon, and backend behavior match.
